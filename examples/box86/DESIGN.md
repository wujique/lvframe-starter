# box86 工程设计文档

## 概述

本工程是一个智能家居中控屏的 UI 应用程序，基于 LVGL 9.4 和 lvframe 页面管理框架开发。

- **UI 渲染**：基于 lvframe 的多页面管理，支持左右滑动切换设备页、下拉进入设置页等交互
- **业务逻辑**：设备数据模型管理，支持通过 Shell 命令行与 UI 双向联动
- **UI 与业务交互**：LVGL 和业务逻辑运行在各自独立的线程中，通过 lvframe 事件总线传递消息解耦。UI 操作（如点击按钮）触发消息发往业务线程，业务线程修改数据模型后输出 Shell 日志；Shell 输入指令由业务线程解析，修改模型后通知 UI 刷新。添加/删除设备是特殊操作，需严格管理生命周期：删除时必须先销毁 UI 页面再释放数据模型，防止 UI 回调访问已释放内存导致崩溃；UI 只持有设备 ID，通过只读数据快照读取模型数据，业务线程是数据模型的唯一所有者。详见「线程架构与业务交互」章节。

## 页面结构

```
┌──────────────────────────────────────────┐
│           设备页（主页面区域）              │
│   [设备页1] ←─ 左右滑动 ─→ [设备页N]      │
│   普通灯 / 色温灯 / 电动窗帘，支持多实例    │
└─────────────────┬────────────────────────┘
                  │ 仅第一页支持下拉
                  ▼
┌──────────────────────────────────────────┐
│                 设置页                    │
│        [网络开关]    [更多设置]            │
└─────────────────┬────────────────────────┘
                  │ 上拉返回首页
                  │ 点击"更多设置"
                  ▼
┌──────────────────────────────────────────┐
│              更多设置页                   │
│   [音量设置]  [屏幕设置]  ...（可滚动）    │
└─────────────────┬────────────────────────┘
                  │ 点击具体入口
                  ▼
┌──────────────────────────────────────────┐
│          具体设置页（音量 / 屏幕）          │
│          左上角返回按钮                    │
└──────────────────────────────────────────┘
```

## 各页面设计

### 设备页 — 普通灯

|------|------|------|

| 开关按钮 | Button | 点击切换开/关状态 |
| 状态 Label | Label | 显示当前状态（"已开启" / "已关闭"） |

### 设备页 — 色温灯（继承普通灯）

| 元素 | 类型 | 说明 |
|------|------|------|
| 设备名称 | Label | 显示设备名称 |
| 开关按钮 | Button | 点击切换开/关状态 |
| 状态 Label | Label | 显示当前状态 |
| 色温滑动条 | Slider | 调节色温，范围 2700K ~ 6500K |
| 色温值 Label | Label | 实时显示当前色温值（如"4000K"） |

### 设备页 — 电动窗帘

| 元素 | 类型 | 说明 |
|------|------|------|
| 设备名称 | Label | 显示设备名称 |
| 打开按钮 | Button | 发送 OPEN 指令 |
| 关闭按钮 | Button | 发送 CLOSE 指令 |
| 停止按钮 | Button | 发送 STOP 指令 |
| 开合度 Label | Label | 显示当前开合度（如"75%"） |

### 设置页

| 元素 | 类型 | 说明 |
|------|------|------|
| 网络开关按钮 | Button | 切换网络开/关；开启时按钮为金黄色 |
| 更多设置按钮 | Button | 点击进入更多设置页 |

进入方式：仅从第一设备页下拉进入；上拉返回首页。

### 更多设置页

| 元素 | 类型 | 说明 |
|------|------|------|
| 返回按钮 | Button | 左上角，返回设置页 |
| 音量设置入口 | List Item | 点击进入音量设置页 |
| 屏幕设置入口 | List Item | 点击进入屏幕设置页 |

列表平铺展示，超出屏幕高度时可滚动。

### 音量设置页 / 屏幕设置页

暂不设计页面内容，仅作为占位页面，左上角有返回按钮。

## 设备管理

- 设备支持动态添加和删除（通过 Shell 命令）
- 默认启动时创建一个普通灯设备
- 设备页顺序通过 Shell 命令调整，第一页为首页
- 所有设备类型均支持多实例

### 设备类型

| 类型 | 继承关系 | 功能 |
|------|----------|------|
| 普通灯（light） | 基类 | 开关控制 |
| 色温灯（cct_light） | 继承普通灯 | 开关 + 色温调节 |
| 电动窗帘（curtain） | 独立 | 开/关/停止 + 开合度 |

## Shell 命令行接口

### 命令格式

```
<动作> <目标> [参数...]
```

### 设备管理命令

| 命令 | 说明 | 示例 |
|------|------|------|
| `add light <name>` | 添加普通灯 | `add light 客厅灯` |
| `add cct_light <name>` | 添加色温灯 | `add cct_light 卧室灯` |
| `add curtain <name>` | 添加电动窗帘 | `add curtain 阳台窗帘` |
| `del <id>` | 删除设备，对应设备页立即从 UI 移除 | `del 2` |
| `list` | 列出所有设备及其 ID | `list` |
| `move <id> <position>` | 调整设备页顺序（position 从 0 开始） | `move 3 0` |

### 设备控制命令

| 命令 | 说明 | 示例 |
|------|------|------|
| `set <id> onoffsta <0\|1>` | 设置开关状态 | `set 1 onoffsta 1` |
| `set <id> color_temp <value>` | 设置色温（2700~6500） | `set 2 color_temp 4000` |
| `set <id> position <value>` | 设置窗帘开合度（0~100） | `set 3 position 75` |
| `set <id> command <OPEN\|CLOSE\|STOP>` | 发送窗帘指令 | `set 3 command OPEN` |
| `get <id>` | 查询设备当前状态 | `get 1` |

### 系统控制命令

| 命令 | 说明 | 示例 |
|------|------|------|
| `set system brightness <value>` | 设置屏幕亮度（0~100） | `set system brightness 80` |
| `set system volume <value>` | 设置音量（0~100） | `set system volume 50` |
| `set system network <0\|1>` | 设置网络开关 | `set system network 1` |
| `get system` | 查询系统状态 | `get system` |

### UI → Shell 输出格式

当 UI 操作改变设备参数时，Shell 输出如下格式的日志：

```
[UI] set <id> <field> <value>
[UI] set system <field> <value>
```

示例：
```
[UI] set 1 onoffsta 1
[UI] set 2 color_temp 3500
[UI] set system network 0
```

## 线程架构与业务交互

### 线程模型

本工程采用双线程架构：

| 线程 | 职责 |
|------|------|
| LVGL 线程 | 运行 LVGL 主循环，处理所有 UI 渲染和触摸事件 |
| 业务逻辑线程 | 读取 Shell 输入，维护设备数据模型，驱动 UI 刷新 |

两个线程通过 lvframe 的事件总线（`event_bus`）传递消息，**不直接共享数据结构**，避免竞态条件。

### 消息流向

```
用户触摸 UI
    │
    ▼
LVGL 线程（UI 事件回调）
    │  发送消息到业务逻辑线程
    │  MSG: SET_PROP / SYSTEM_SET
    ▼
业务逻辑线程
    │  修改设备数据模型
    │  Shell 输出属性变化日志
    └─ [UI] set <id> <field> <value>

Shell 输入指令
    │
    ▼
业务逻辑线程（解析命令）
    │  修改设备数据模型
    │  发送消息到 LVGL 线程
    │  MSG: UI_REFRESH / ADD_DEVICE / DEL_DEVICE
    ▼
LVGL 线程（UI 刷新回调）
    └─ 更新对应设备页的显示内容
```

### 消息类型定义

| 消息类型 | 方向 | 说明 |
|----------|------|------|
| `MSG_SET_PROP` | UI → 业务 | UI 操作触发属性变更（开关、色温、窗帘指令等） |
| `MSG_SYSTEM_SET` | UI → 业务 | UI 操作触发系统属性变更（网络开关等） |
| `MSG_UI_REFRESH` | 业务 → UI | 通知 UI 刷新指定设备页的显示内容 |
| `MSG_ADD_DEVICE` | 业务 → UI | 通知 UI 新增一个设备页 |
| `MSG_DEL_DEVICE` | 业务 → UI | 通知 UI 删除指定设备页 |
| `MSG_MOVE_DEVICE` | 业务 → UI | 通知 UI 调整设备页顺序 |

### 设备生命周期管理

添加和删除设备是两个特殊操作，需要同时管理数据模型和 UI 页面，且必须保证顺序安全。

**添加设备流程：**
1. 业务逻辑线程创建设备数据模型，分配唯一 ID
2. 发送 `MSG_ADD_DEVICE`（携带设备 ID 和类型）到 LVGL 线程
3. LVGL 线程在主循环中创建对应设备页，页面持有设备 ID（不持有模型指针）
4. 设备页通过 ID 向业务逻辑线程查询数据，不直接访问模型内存

**删除设备流程（关键：防止 UI 访问已释放的模型）：**
1. 业务逻辑线程发送 `MSG_DEL_DEVICE`（携带设备 ID）到 LVGL 线程
2. **等待 LVGL 线程确认页面已销毁**（同步点，防止 UI 回调访问悬空指针）
3. LVGL 线程销毁对应设备页及其所有 UI 控件，回复确认
4. 业务逻辑线程收到确认后，释放设备数据模型内存

> 删除时必须先销毁 UI 页面，再释放数据模型，顺序不可颠倒。

### UI 页面与数据模型的解耦原则

- UI 页面**只持有设备 ID**，不持有模型指针
- UI 需要读取数据时，读取业务逻辑线程维护的只读数据快照（业务线程在修改模型后同步更新快照）
- 业务逻辑线程是数据模型的唯一所有者，负责其创建和释放
- LVGL 线程是 UI 控件的唯一所有者，负责其创建和销毁
