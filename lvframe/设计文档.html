1方案概述与设计原则

本框架为基于 LVGL 的嵌入式设备提供完整的 UI 管理方案。v2 相对 v1 的核心变化：

事件总线 → 消息槽（Slot）
任何线程可向任一槽发送消息（signal + object + payload）；每个槽只有一个消费者线程。QT 信号-槽风格，取代 event_bus / app_bus / adapter 三套机制。
数据模型完全移出框架
lvframe 不定义、不管理、不存储任何数据模型；object 仅是不透明路由键（只做指针比较），模型/虚拟抽象全部归应用层。
信号式订阅，对象匹配上移
订阅按信号 + 对象维度（对象可空 = 全收）；对象匹配由槽在分发时完成，回调不再做实例过滤，payload 语义由回调自决。

1.1 设计原则

  • 能力边界：lvframe 只提供两类能力——消息槽与页面生命周期栈（含左右滑动页管理）。数据模型（设备或用户自定义结构体）的定义、存储、使用方式，以及"何时添加/删除页面"的决策逻辑，全部归应用层。
  • 消息语义由应用定义：框架只提供骨架（signal + object + payload + 便捷参数），不做任何业务假设。
  • 槽按"信号 + 对象"分发：队列 + 信号匹配 + 对象匹配（NULL 双向通配）+ 快照安全；object 匹配由槽完成，payload 路由由回调自决。
  • payload 所有权一次性移交：调用方在 send 后不再触碰 payload；槽在分发结束后负责释放（可选析构，默认 lv_free）；object 永不释放。
  • object 不透明：槽对 object 只做指针 == 比较，不读写其内容、不释放、不假设它是"数据模型"；其语义与生命周期完全由应用层决定。
  • 零闲置内存：消息队列与订阅表均为动态链表节点，完全无上限，不预分配容量。
  • 跨线程只有消息槽一条通道：UI 点击经槽发往业务线程，业务变更经槽通知 UI；数据读取走仓库快照（互斥锁内拷贝）。

本文档为 v2 设计（动态节点、信号 + 对象匹配、payload 由槽释放）。方案未定，审核通过前禁止修改代码。

3槽组件（lv_slot）设计

3.1 概念：与 QT 信号-槽的对应

QT 概念本设计
Signal（信号）lv_slot_send()：任意线程发送消息（signal + object + payload）到槽
Slot（槽）一个 lv_slot_t：消息队列 + 订阅者链表 + 唯一消费者线程
connect（连接）lv_slot_subscribe(slot, signal, object, handler, ctx)：按信号 + 对象订阅
Receiver 对象Page（page_bind_slot）或任意应用对象（ctx）
匹配/过滤信号 + 对象由槽匹配（object 为 NULL 时双向通配）；payload 语义由回调自决

3.2 设计目标

  • 任意线程可发送：任何线程向任一槽发送消息，非阻塞、互斥保护。
  • 槽归属消费者线程：每个槽只属于一个消费者线程（g_ui_slot 属 UI 线程、由 LVGL 定时器消费；g_dev_slot 属 DEV 线程、由业务线程消费）；其他线程只向该槽发送消息。
  • 消息语义应用化：signal / object / payload 语义由应用定义，框架不做业务假设。
  • 信号式订阅：订阅按信号（signal）+ 对象（object）维度；一对象可细分多信号。
  • 对象匹配上移：槽在分发时按 signal + object 过滤（NULL 双向通配），回调不再做实例过滤。
  • payload 由槽释放：动态申请负载在分发结束后由槽统一释放（可选析构）；object 永不释放。
  • 零闲置内存：消息队列与订阅表均为动态链表节点，完全无上限。

3.3 数据结构（动态链表，零闲置内存）

#define LV_SLOT_NAME_MAX 24

/* 消息骨架：signal / object / payload 语义完全由应用定义 */
typedef struct {
    int   signal;                /* 信号（signal/event）：应用枚举 */
    void* object;                /* 对象：不透明指针（仅 == 比较）；NULL = 广播；槽永不释放、不读写内容 */
    void* payload;               /* 负载，槽不关心内容；动态申请由槽负责释放；NULL = 无负载 */
    void  (*payload_dtor)(void*); /* payload 析构（payload != NULL 时于分发结束后调用）：
                                   *   NULL        → 槽用 lv_free 释放；
                                   *   自定义函数  → 释放嵌套指针等；
                                   *   空函数 no-op → 不需要释放（借用/静态 payload）。*/
    int   arg0, arg1;            /* 便捷整型参数（box86: value / new_pos）*/
    double argf;                 /* 便捷浮点参数（如空调温度，0.1 精度）*/
    char  field[24];             /* 便捷字符串参数（box86: 属性名）*/
} lv_slot_msg_t;

typedef void (*lv_slot_handler_t)(void* ctx, const lv_slot_msg_t* msg);

/* 消息节点：发送时动态申请（lv_malloc），分发后连同 payload 一起释放 */
typedef struct lv_slot_node {
    lv_slot_msg_t        msg;
    struct lv_slot_node* next;
} lv_slot_node_t;

/* 订阅者节点：订阅唯一身份 = (signal, object, handler, ctx) 四元组，动态申请，无数量上限 */
typedef struct lv_slot_sub {
    int                 signal;  /* 订阅的信号类型 */
    void*               object;  /* 订阅的对象；NULL = 该信号全接受（不管发送方是否指定对象）*/
    lv_slot_handler_t   handler; /* 订阅回调；退订时作为身份一部分（函数指针 == 比较）*/
    void*               ctx;     /* 订阅者对象（Page* 或任意）*/
    struct lv_slot_sub* next;
} lv_slot_sub_t;

typedef struct {
    char             name[LV_SLOT_NAME_MAX];  /* 槽名："g_ui_slot" / "g_dev_slot" */
    lv_slot_node_t*  head;                    /* 队头（消费者出队）*/
    lv_slot_node_t*  tail;                    /* 队尾（发送方追加）*/
    int              count;                   /* 待处理消息数（诊断）*/
    lv_mutex_t       mutex;                   /* 保护队列与订阅链表 */
    lv_thread_sync_t sem;                     /* 入队 signal，唤醒阻塞消费者 */
    lv_slot_sub_t*   subs;                    /* 订阅者链表 */
    int              sub_count;
    int              dropped;                 /* 分配失败丢弃计数（诊断）*/
} lv_slot_t;

3.5 实现要点

  • 发送流程（lv_slot_send）：lv_malloc 消息节点 → 加锁尾插链表 → 解锁 → lv_thread_sync_signal 唤醒阻塞消费者 → 返回。完全无上限，节点分配失败时释放 payload并 dropped++ 兜底。send 一旦调用，payload 所有权即移交槽，调用方不再触碰。
  • 分发流程（lv_slot_process，唯一消费者线程）：
    1. while(1) 循环出队直到队列为空（批量处理，避免延迟累积）；
    2. 对每条消息，锁内收集订阅者快照（动态数组，随节点释放）再解锁；
    3. 匹配规则：sub->signal == msg->signal && (sub->object == NULL || msg->object == NULL || sub->object == msg->object) → 调用 handler(ctx, msg)；完整消息原样透传（object 已由槽过滤）；
    4. 所有订阅回调返回后，释放 payload（payload_dtor 非空则调用之、否则 lv_free；no-op 即不释放）并 lv_free 释放消息节点。
  • 线程安全：队列与订阅链表共用一把互斥锁；快照机制保证回调内可安全订阅/退订、可再 send（重入无碍），无死锁。
  • 职责边界：槽 = 队列 + 按 signal + object 分发 + payload 生命周期管理；payload 语义解释与使用 = 订阅回调；object 生命周期 = 应用层（槽不释放、不假设）。

3.6 消费模式

模式适用说明
slot_wait() + slot_process()DEV 线程（g_dev_slot）可安全阻塞，消息响应即时；Shell 轮询与槽消费在同一循环
LVGL 定时器回调 slot_process()UI 线程（g_ui_slot）50ms 周期；UI 线程运行 lv_timer_handler 不可阻塞

一个槽只允许一个消费者线程（设计约束，由应用指定）。槽以消费者线程命名并归属之：g_ui_slot 是 UI 线程的槽、g_dev_slot 是 DEV 线程的槽，其他线程只向其发送消息；槽机制本身不硬绑定线程，消费方式（wait+process 或定时器）由应用选择。

3.7 payload 所有权契约与退订语义

payload 所有权：调用方构造 lv_slot_msg_t 并调用 lv_slot_send() 后即视为一次性移交所有权，此后调用方不得再读写或释放 payload。槽在以下路径保证释放 payload 且仅释放一次：

  1. 消息节点分配失败 → 立即释放 payload（dropped++）；
  2. 正常入队 → 分发结束后（所有订阅回调返回）释放 payload；
  3. 槽 deinit 时残留队列 → 逐节点释放 payload。

释放方式：payload_dtor 非空则调用 payload_dtor(payload)，否则 lv_free(payload)。若 payload 不需要释放（借用/静态数据），传一个空函数（no-op）作为 payload_dtor，槽即不释放；切勿对借用指针留 NULL（会触发 lv_free）。多个订阅者共享同一份只读 payload，回调内如需保留数据必须自行拷贝。object 为不透明指针，槽永不释放、不读写，其生命周期由应用层（如 box86 的模型仓库 + 两段式删除）保证。

退订语义（对齐 Qt disconnect）：订阅节点的唯一身份为四元组 (signal, object, handler, ctx)（handler 用函数指针 == 比较）。同一信号下可有多个对象（含 NULL）以同一 ctx 订阅，因此退订必须携带足够字段才能唯一定位：

  • lv_slot_unsubscribe_all(slot, ctx)：移除该 ctx 的全部订阅（不分 signal/object/handler），用于 page_destroy；
  • lv_slot_unsubscribe_one(slot, signal, object, handler, ctx)：四元组全等才删除，最多命中一个节点（因订阅时按四元组去重）；命中移除返回 0，未命中返回 -1；
  • page_unbind_slot(page, slot, signal, object)：Page 层封装，内部 handler 固定为 page_slot_dispatch，应用层无需关心 handler。

4订阅与匹配机制（信号 + 对象）

订阅指明信号（signal）与对象（object）两个维度。信号匹配无歧义（sub->signal == msg->signal）；对象匹配采用语义 B：NULL 双向通配——任一侧 object 为 NULL 都命中，用于表达"广播"与"全收"。匹配由槽在分发时完成，回调不再做实例过滤。

对象匹配真值表（X / Y 为具体对象指针）：

订阅 object消息 object命中说明
NULL（全收）NULL（广播）✅全收订阅者收到广播
NULL（全收）X✅全收订阅者收到任意对象消息
XNULL（广播）✅广播命中精确订阅者（NULL 双向通配）
XX✅对象精确匹配
XY❌对象不匹配，不投递

匹配伪代码：

sig_match = (sub->signal == msg->signal);
obj_match = (sub->object == NULL) || (msg->object == NULL) || (sub->object == msg->object);
if (sig_match && obj_match) handler(ctx, msg);   /* 完整消息原样透传 */

三种典型场景：

  • 多实例精确匹配：3 个灯页分别以各自模型为 object 订阅 LIGHT_ON/OFF；槽只把消息投给 object 命中的那一页。
  • 一模型多 UI：tile 页与信息浮层用同一 object 订阅同一信号，同一条信号同时命中两处。
  • 信号级广播：发送 object=NULL 的消息（如"全屋断电"）；精确订阅者会因 NULL 双向通配而命中，回调内如需区分广播可判断 msg->object == NULL。

语义 B 下精确订阅者会被广播命中；若希望"广播只命中心广播订阅者"，应改用语义 A（仅 sub->object == NULL 命中广播）。本方案选定 B。

5.5 实现要点

  • 创建流程：calloc → 创建 root（隐藏、清样式）→ 全局 root 回调 → 复制 lifecycle → CREATED → on_create。
  • 销毁流程：若 page->slot 非空则 lv_slot_unsubscribe_all(slot, page) → on_destroy → lv_obj_delete(root) → free。
  • 绑定流程（page_bind_slot）：校验参数 → lv_slot_subscribe(slot, signal, object, page_slot_dispatch, page)（内部 handler 调用 page->lifecycle.on_msg）→ 记录 page->slot。重复订阅同一 (signal, object) 时去重。
  • 退订流程：page_destroy 自动 lv_slot_unsubscribe_all(slot, page)；如需单条退订，应用调用 page_unbind_slot(page, slot, signal, object)（内部四元组 (signal, object, page_slot_dispatch, page) 全等匹配）。
  • 回调匹配约定：on_msg 收到的是已按 signal + object 过滤的消息，无需再做实例过滤，是否处理由页面自行决定。

页面 on_msg 示例（object 已由槽过滤）：

static void device_page_on_msg(Page* page, const lv_slot_msg_t* msg)
{
    /* msg->object 已由槽匹配，无需再做实例过滤 */
    switch (msg->signal) {
    case MSG_DEV_LIGHT_ON:   light_refresh(page); break;
    case MSG_DEV_LIGHT_OFF:  light_refresh(page); break;
    }
}
  • 订阅时机：on_create 中调用 page_bind_slot（每个 (signal, object) 一次）；退订由 page_destroy 自动完成。
  • 非 Page 的 UI 对象（如设置面板）：使用原始 lv_slot_subscribe(slot, signal, object, handler, ctx)，销毁前手动 unsubscribe_all。
  • 读数据：由应用层自行完成（box86 走模型仓库快照，锁内拷贝）；lvframe 不参与数据读写。

6页面管理器（PageManager）

接口与行为保持 v1：注册表（≤20）、导航栈（≤20）、LRU 缓存（默认 3 / 上限 10）、错误码返回。删除 page_manager_find_page_by_model（模型相关能力，改由槽按 object 匹配 + 应用层管理完成）。

typedef enum {
    PAGE_MANAGER_OK = 0,
    PAGE_MANAGER_ERR_NOT_FOUND,    /* 页面未注册 */
    PAGE_MANAGER_ERR_STACK_FULL,   /* 页面栈满 */
    PAGE_MANAGER_ERR_NULL_POINTER, /* 空指针参数 */
    PAGE_MANAGER_ERR_INTERNAL,     /* 创建失败 */
} PageManagerError;
  • 打开：旧页 on_pause + 隐藏 → 缓存查找或工厂创建 → on_start / on_resume + 显示 → 压栈（记录名称）→ 旧页 on_stop；失败时恢复当前页并返回错误码。
  • 返回：栈顶 on_pause → on_stop + 隐藏 → 上一页恢复 → 当前页按名称入缓存。
  • 缓存：数组 + 移位实现，命中即取出，满时淘汰最旧；缓存恢复的页面保留 UI 状态。

7滑动容器抽象层 + TileView 实现

typedef struct {
    lv_obj_t* (*create)(lv_obj_t* parent);
    lv_obj_t* (*add_page)(lv_obj_t* container, int index);
    void      (*remove_page)(lv_obj_t* container, int index);
    void      (*switch_to)(lv_obj_t* container, int index);
    int       (*get_current)(lv_obj_t* container);
    int       (*get_count)(lv_obj_t* container);
} SwipeContainerOps;
  • 注册表（≤5），create 实现须把 ops 存入容器 user_data；
  • tileview_impl（v9.4）：tile 以 user_data=1 标记；删除后手动重排 lv_pct(i*100) 坐标；切换带动画（LV_ANIM_ON）。

SwipeContainer 只提供左右滑动页的原语（增/删/切换/查询）；何时增删页、每页放什么内容、如何与数据模型关联，由应用层决策（如 box86 在 ADD_MODEL / DEL_MODEL 时增删 tile）。

8数据模型（应用层，不属于 lvframe）

lvframe 不定义、不管理、不存储任何数据模型。数据模型（如 box86 的 model_base_t / model_store / 灯·色温灯·窗帘·SYSTEM 模型）完全属于应用层，详见 box86 工程设计文档 §5。

lvframe 与模型的唯一交互点是消息槽的 object 字段：它只是不透明指针，槽仅按指针 == 匹配、不读写内容、不释放；object 的语义（是设备还是虚拟抽象）与生命周期由应用层自行定义与保证。

13错误处理与调试

  1. 空指针/边界检查：槽与 Page 所有公共 API 均做参数防御。
  2. 分配失败：lv_slot_send 返回 -1 并 dropped++；应用可周期性打印 dropped 监控内存压力。
  3. 悬垂订阅：page_destroy 自动 unsubscribe_all，杜绝页面销毁后仍被分发。
  4. 悬垂对象：两段式删除（先销毁 UI 页面再释放模型）+ 槽按 object 指针匹配（object 不透明、槽不释放）；对象有效性由应用层模型自身管理。
  5. 调试日志：槽初始化/订阅/发送/分发打印关键路径（slot/页面/业务 前缀）。

14扩展指南

  1. 新增信号：在应用 msg.h 枚举中追加（框架零改动）；定义 object / payload 语义；页面按需订阅。
  2. 新增槽：lv_slot_init 创建 → 指定消费者线程（wait+process 或定时器 process）。
  3. 信号级广播：发送 object=NULL 的广播消息；精确订阅者因 NULL 双向通配命中，回调内如需区分广播可判断 msg->object == NULL。
  4. 回调过滤策略：多实例（订阅时 object=对象，槽已过滤）、类型过滤（应用层自行强转 object 读取其类型）、全收（订阅 object=NULL）——实例维度已由槽完成，回调只做业务处理。
  5. 新增对象/模型类型：属应用层职责（box86：定义模型结构 → 注册类型枚举 → 实现 add/set/snapshot → 页面以 object 订阅），lvframe 零改动。

15已知限制

  1. 消息队列完全无上限：生产速率长期大于消费速率时内存可能持续增长（依赖 lv_malloc 失败丢弃兜底，无水位线）。
  2. 一个槽仅一个消费者线程（设计约束，代码不做强制校验）。
  3. 消息只携带指针与便捷参数，无法携带大块数据（大负载需应用自定义共享结构）。
  4. object 为裸指针，其有效期依赖"两段式删除"保证；语义 B 下广播会命中精确订阅者，回调如需区分广播须自行判断 msg->object == NULL。

17.1 验证计划（代码实施后执行）

  1. 编译：cmake + SDL 构建，消除全部告警；
  2. 信号匹配：开灯只发 LIGHT_ON，仅订阅 LIGHT_ON 的页面响应；关灯同理；
  3. 多实例匹配：添加 3 个灯，set 其中一个，仅对应页面刷新（回调 payload 匹配）；
  4. 一模型多 UI：打开设备信息浮层，同一条 LIGHT_ON 同时刷新 tile 页与浮层；
  5. 信号广播：ALL_LIGHTS_OFF 广播，所有灯页响应、窗帘页不响应；
  6. 删除握手：del 后先销毁页面再释放模型，`get` 查询报不存在；长时间运行无内存增长；
  7. 线程安全：并发 Shell 命令 + UI 点击，无崩溃、无数据竞争告警；
  8. 零闲置内存：空闲时队列无残留节点（count=0，无预分配）。

18总结

  • 统一通信原语：槽取代 event_bus/app_bus/adapter 三套机制，任意线程发送、单消费者按 signal + object 分发。
  • 能力边界：lvframe 只提供消息槽 + 页面生命周期栈（含左右滑动页管理）；数据模型及其使用、页面增删决策完全归应用层。
  • 对象匹配上移：signal + object 匹配由槽完成（NULL 双向通配）；payload 语义与业务路由由回调自决。
  • 零闲置内存：队列与订阅表动态链表，无预分配容量。
  • 生命周期安全：页面自动退订 + 模型两段式删除，杜绝悬垂。
